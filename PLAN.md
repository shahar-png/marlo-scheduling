# PLAN — Public booking page front-end (BOOK-FE)

Spec owner: Shahar + VP of Product · Product review: Shahar + Grok · Plan review: Codex (BLOCKED → revised → REVISE → revised → REVISE → revised → REVISE → revised) · Status: APPROVED Founder go + VP Product (plan revise after Codex REVISE BOOK-FE-08), 20 Sep 2026 ET

## Goal

An invitee can open a **public booking route**, pick a date/slot, enter name/email, and confirm a booking — **Marlo-branded UI** from the FE handoff — wired to the **existing** in-repo booking APIs. `https://marlo-scheduling.vercel.app` is no longer a placeholder-only homepage: `/` is branded cream/ink/lime chrome that links to a bookable demo, and `/{slug}/{event}` is a real booking page. After confirm, `/b/{token}` shows a branded “Handled.” confirmation shell. All handoff↔repo mapping lives in `lib/api/` (components never `fetch`). The page never offers, keeps offering, selects, or confirms a start that has already elapsed — the cutoff is re-evaluated against a **fresh clock** when availability resolves, while the picker stays open, at selection, and at submit. Production dependencies (API helpers, router navigation, clock) are created **inside client components**; the Server page passes only serializable props. An availability window that has fully elapsed yields empty availability, never a backend error. A group session whose last seat is taken (409 `session_full`) recovers the same way a taken 1:1 slot does — branded copy, selection cleared, availability refreshed. One submit gesture produces **at most one** `createBooking` call: while a request is in flight (and after success, until navigation completes) the submit control is disabled and any re-entry into the submit handler is a synchronous no-op, so a double-click or repeated Enter never creates two bookings.

5. **Booking UI (handoff 6.1–6.2 spirit, time-boxed) — must be testable as a real form under `tsx --test`:**

It keeps the raw `times` in state and derives the **offered** list as `times.filter(start >= now())` at render, where `now` is the injected clock. To make that derivation re-run as time advances it holds a `tick` state bumped by (i) a `setInterval` (≈30 s; the interval factory — `setInterval`/`clearInterval` or a `schedule` prop — is injected alongside `now` so tests can fire it deterministically, no fake global timers), (ii) `window`/form `focus` and `visibilitychange` handlers, and (iii) every slot selection. When the tick removes the currently selected start, the selection is cleared. Expired controls are removed (or rendered disabled with `aria-disabled`); either way they are not selectable.

This covers the window between an expired control still being on screen and the next tick.

Renders `<BookingForm ... api={api} navigate={navigate} now={now} />`.

Receives `api`, `navigate`, `now` **by props from its client parent** (no defaults that reach for globals). Dependency injection is client→client only; RSC serialization is never asked to carry a function.
   - **In-flight submit guard (BOOK-FE-08) — first thing in the submit handler:** the handler owns a synchronous latch (`pendingRef = useRef(false)` or an equivalent closure variable; **not** solely a `useState` flag, because state set inside the handler is not visible to a second call in the same tick). Order of operations in `onSubmit(e)`: `e?.preventDefault()` → `if (pendingRef.current) return;` → `pendingRef.current = true` → `setPending(true)` (drives the disabled control) → elapsed recheck → `await api.createBooking(...)`.
