## Goal

An invitee can open a **public booking route**, pick a date/slot, enter name/email, and confirm a booking — **Marlo-branded UI** from the FE handoff — wired to the **existing** in-repo booking APIs. `https://marlo-scheduling.vercel.app` is no longer a placeholder-only homepage: `/` is branded cream/ink/lime chrome that links to a bookable demo, and `/{slug}/{event}` is a real booking page. After confirm, `/b/{token}` shows a branded “Handled.” confirmation shell. All handoff↔repo mapping lives in `lib/api/` (components never `fetch`). The page never offers, keeps offering, selects, or confirms a start that has already elapsed — the cutoff is re-evaluated against a **fresh clock** when availability resolves, while the picker stays open, at selection, and at submit. Production dependencies (API helpers, router navigation, clock) are created **inside client components**; the Server page passes only serializable props. An availability window that has fully elapsed yields empty availability, never a backend error. A group session whose last seat is taken (409 `session_full`) recovers the same way a taken 1:1 slot does — branded copy, selection cleared, availability refreshed. One submit gesture produces **at most one** `createBooking` call: while a request is in flight (and after success, until navigation completes) the submit control is disabled and any re-entry into the submit handler is a synchronous no-op, so a double-click or repeated Enter never creates two bookings. The picker has **one notion of "month"**: the displayed time zone's. The initial month, the `getSlots` query bounds, the day grouping, and month-boundary recovery all use the same displayed time zone (never UTC when the invitee is not in UTC), so a start that is Oct 1 on the invitee's wall clock is listed under October and is found by the October query — for any positive or negative UTC offset. A month is a window of **start** instants: a meeting that starts inside the displayed local month but ends after local month-end still belongs to that month and is still offered — the `lib/api` adapter widens the backend query's upper bound by the event duration (the existing slot engine excludes any meeting whose *end* exceeds `timeMax`) and then filters the returned starts back to the logical month window, so no bookable start disappears from both months. A malformed email address never reaches the backend: syntax is validated in the form before `createBooking` — one `@`, a non-empty local part, a domain of at least two dot-separated labels **every one of which is non-empty** (`a@b..co`, `a@.b.co`, `a@b.co.` are rejected), and no whitespace — `details.errors.email` is shown, the selected slot is kept, and the submit latch is released so the invitee can correct it. The confirmation page reflects the booking's `status`: active copy and meeting details only for a `confirmed` row; a row cancelled through the existing cancel route renders the existing cancellation copy inside the same branded shell. The cancelled shell never carries a broken link: `cancel.bookAgain` is rendered **only** when the adapter resolves a valid public booking URL for a reusable event type; a cancelled one-off booking (made through the existing single-use-link path, whose synthetic event type is not in the event-type store) keeps the cancellation shell and simply omits the link. The invitee sees **one host** from booking page to confirmation: host chrome (first name in `booking.headline`, the avatar initial, `confirmation.subhead`, `cancel.done`, the with-line, and the `cancel.bookAgain` destination) comes from the **canonical host metadata of the event being booked**, never from the URL `[slug]` — the demo event is hosted by `host-1` / Marlo, so only the `demo` host alias is valid for it, and an unsupported alias such as `/alice/intro-30` is canonicalized to `/demo/intro-30` rather than rendered as a person named “Alice”. The confirmation route holds the same line: a booking row whose `hostId` has **no canonical host** (the shared booking store already accepts such rows — e.g. `host-2` booked through the existing `bookAvailableSlot`) is never attributed to Marlo by fallback; `/b/{id}` for it, confirmed or cancelled, renders the branded `states.notFound` shell with **no host attribution, no meeting details, and no book-again link**, and the adapter produces `bookAgainHref` only when it resolved **both** a canonical host **and** a store-backed public event type. That shell is still **Marlo-branded** — the Logo and the `brand.poweredBy` footer (“Scheduled with Marlo”) stay, as on every other state — so “no host attribution” means no substituted host first name, no `confirmation.subhead` / `cancel.done`, no with-line, and no booking link; it does not mean the product name is scrubbed from the page. Every public path the product emits is **constructed, never interpolated**: one shared constructor percent-encodes representable slug segments and rejects unrepresentable ones (`/`, `\`, `?`, `#`, control characters, empty, `.`, `..`), and it is the only way the canonical redirect, `bookAgainHref`, and the event-slug segment of a `lib/api` request path are built — an event type whose store-accepted slug cannot be represented (e.g. `intro#follow-up`) has no public booking page, produces no redirect, no book-again link, and no misparsed API request, rather than a URL that resolves to a different event. `bookAgainHref` is a property of the **row's resolvability**, not of its `status`: the adapter attaches it whenever a canonical host, a store-backed event type, and a representable path all resolve — for a confirmed row as much as for a cancelled one — and only the cancelled page branch turns it into the `cancel.bookAgain` anchor. The confirmation and cancel-done heroes fit a 390px-wide viewport without horizontal overflow: under the mobile breakpoint the hero is the handoff §6.3 **64px** size, and the desktop hero stays 112px as designed.

The fix is a single constructor in `lib/api/public-path.ts` that percent-encodes representable segments (`encodeURIComponent`; `café 30` → `caf%C3%A9%2030`, which Next's param decoder round-trips) and rejects the delimiters and non-round-tripping inputs outright (`/`, `\`, `?`, `#`, control characters, empty, `.`, `..`, lone surrogates).
